# mkbot

mkbot 是一个正在开发的自主角色框架。角色拥有持续状态、经历、关系、计划和可组合的插件能力。

当前已实现可运行的内核、管理面板、外层调度、有界主会话、统一模型网关、插件 SDK 和第一版分层记忆。项目仍处于早期开发，尚未接管线上 QQ；真实渠道、角色关系、具体技能和完整的记忆整理流程仍在建设中。

## 本地开发

需要 Python 3.12+ 和 uv。

```powershell
uv sync --group dev
uv run pytest
uv run mkbot init
uv run mkbot serve
```

默认监听 `127.0.0.1:8096`。实例数据放在 `.data/`，管理令牌写入 `.data/admin-token`。
接口采用 Bearer 认证。实例目录和令牌不应提交到 Git。

管理面板可以配置人格、模型路由与价格，并手动运行一轮活动。默认没有供应商或模型路由，自动调度也默认关闭，因此首次启动不会产生模型费用。`uv run mkbot --help` 查看命令；指定实例目录时，将 `--data-dir PATH` 放在 `init` / `serve` 前面。

## 管理面板

面板参考 MaiBot WebUI 的分组导航、运行概览和明暗主题。当前包含工作台、角色与能力、运行管理三组入口；首页显示真实角色状态、调度原因、模型请求、Token、已结算费用、预留费用和耗时，支持 24 小时 / 7 天 / 30 天统计。没有请求时显示空态，不填充模拟图表。统计按请求开始时间归入区间，费用从全局日账聚合，不重复叠加根活动或自主活动的同一笔支出；平均耗时是成功请求的完整耗时，尚未测量流式首 token。

人格和调度提供表单与完整 JSON 编辑；保存采用版本校验，不覆盖并发修改。记忆页支持来源与范围、修订、遗忘、按受众预览和画像。明暗主题只保存在当前浏览器；配置与状态保存在实例数据库。数据目前通过页面进入或手动刷新更新，界面显示读取时刻。

## 自动调度与作息

在「调度与作息」配置并启用自动调度。外层协调器等待来信、已保存的期限和唤醒时间，不周期性询问模型。连续消息默认合并等待 2 秒、最多等待 10 秒，每批最多 80 条；同一会话默认间隔 10 秒。每批只包含一个会话，模型可用 `life__review` 选择回复、不回复、暂缓或过期。暂缓必须指定未来时刻，默认最多两次；未被接取且已超过 48 小时的留言直接标记过期。

后台活动在模型或工具返回后的安全边界让出前台，保留检查点，之后继续；不会强行取消可能已经产生副作用的调用。连续处理默认 4 批会话后，给到期后台活动一次推进机会。已确认的让路和重试等待不消耗活动执行时限，但原有步骤、尝试次数、费用限制保持不变。

清醒且没有正在处理或待核对的任务时，默认每 30 分钟获得一次自主活动机会，每 UTC 日最多 24 次。角色可使用 `life__wait_until` 安排下一次空闲机会，或使用 `life__sleep` 保存唤醒窗口；漏过的空闲时段不会补跑。自主调用还有独立的日费用和调用次数上限。失败或额度耗尽的活动保留为需要处理，不自动换一个新根活动无限重试。

睡眠时只保存原始留言，不调用模型、记忆工具或发送。醒来后按会话审阅，再恢复自己的活动。这里已实现框架的批次、等待、恢复与预算约束；关系亲密度、生物钟策略和具体内容是否值得回复，仍需要后续关系模块及真实模型验证。现阶段最终回复进入发送队列，真实 QQ 投递适配器尚未接入。

## 模型配置

面板的「模型与路由」保存 `models` 配置。每次新调用读取当前版本，正在执行的请求使用启动时的快照。供应商密钥仅填写环境变量名称，例如 `MKBOT_MODEL_KEY`，不要把密钥写入配置或 Git。

可参照 `examples/models.json` 填入服务地址、模型 ID 和实际渠道价格，再保存到面板。示例中的价格仅为格式演示，不代表任何真实模型报价。`roles.planner` 数组按主用、备用顺序填写；主循环和插件的模型服务共用同一入口。

当前支持非流式 Chat Completions 的文本与工具调用；适配器不做隐藏重试、不自动跟随重定向、不继承进程代理变量。网关负责 180 秒默认超时、持久化尝试次数与退避、备用路由和熔断。响应未提供 usage 时保留预留，实际费用缺失不记成零；现阶段费用是按供应商 token 数和配置价格计算，未与上游账单对账。

`micro_usd` 为百万分之一美元。当前日界为 UTC，日预算与根活动预算共用预留检查；预估并不等同于供应商的硬性计费上限。限次重试、根活动步数和重复无进展检查共同限制调用。

## 插件与主会话

插件以 `Manifest + Tool + PluginContext` 注册。能力描述、专业说明和参数 schema 进入主会话；工具需要额外模型处理时，调用 `context.model()` 继承当前活动预算。内置 `notebook` 是最小可运行示例，笔记按会话保存；它不是长期记忆系统。

主循环保存模型决策、工具结果和执行位置。一个活动的最终文本只进入一次发送队列，实际平台发送通过独立适配器确认回执。外部工具或投递超时保留 unknown，不盲目重做。

Python 插件目前在进程内运行，属于受信代码。SDK 提供统一约定，尚不是防止恶意插件越权访问文件或网络的隔离边界。

## 记忆与画像

工作记忆使用活动检查点，独立于有容量限制的近期记忆。近期记忆包含普通 FIFO 区和有限保护区；长期记忆保存人物偏好、边界、经历及角色自己的兴趣与观点。画像是有效长期记录的视图，使用平台标识与用户 ID 组成的人物身份，角色自身使用 `self`。

内置 `memory` 插件提供召回、保存提议和实际使用标记。主会话可以根据提供的 `source_ref` 保存记录；不存在的来源、自身回声和已经遗忘的来源会被拒绝。事实来源、有效期、修订版本与活跃度分别保存。来源归属不等同于内容已被语义核实：当前仍依赖模型正确提炼内容，标注“本人陈述”不代表系统证明了该陈述真实。

默认私聊来源仅可用于对应会话，群聊来源允许跨会话使用。每条记录分别保存可使用范围与可表达范围；受众过滤发生在进入上下文之前，派生摘要继承范围和最早有效期。`@self` 表示内部范围，`*` 表示全部范围，其他值为精确会话 ID。`share_group_memories` 影响新建来源；修改配置不会追溯改写既有记录的范围。管理员可显式扩大单条记忆的范围。跨会话分享需要为目标受众构建新活动。

界面查看、检索和反复反思不增加强化值。模型声明“用到了”之后，运行时还要验证完成结果/发送回执、真实触发输入和根活动，再按滚动 24 小时额度有限强化。整批输入去重，即使某次因达到上限没有奖励，也不能隔天重放刷分。强化不改变来源、可信类型、亲密度、事件发生时间、有效期或共享范围。

管理面板支持录入、筛选、修改、修订历史、按受众召回预览和人物画像。编辑采用版本校验。遗忘以根来源为单位影响相关记录及派生内容，操作前显示影响条数；旧版本、受管插件笔记、模型结果、活动检查点及待发送草稿会被清理。原始聊天日志保留，但不再从被遗忘的旧来源注入上下文或提炼记忆。在途模型仍正常计费，返回结果被丢弃；已经发出或被平台接受的消息不能靠本地遗忘撤回。

当前检索使用有范围过滤的关键词与活跃度排序，没有接入向量模型或自动批量巩固。角色睡眠期间只收原始事件，不运行提取、检索选入、强化或工具；管理者仍可查看和维护实例。插件依赖传播只覆盖 SDK 管理的状态，不能清理受信插件自行写入的外部文件。

## 代码结构

```text
src/mkbot/
  domain/       类型、错误与状态契约
  storage/      SQLite 事务与版本迁移
  runtime/      时间、生命周期、任务、持久收件和有界主会话
  models/       类型化请求、HTTP 协议、路由和尝试账本
  memory/       来源、近期容量、长期记录、受众召回与遗忘传播
  plugins/      能力契约、受计量上下文、持久工具回执与示例
  actions/      发送队列、回执与重复执行控制
  accounting/   预算预留与用量账本
  api/          管理接口及面板
tests/          行为与故障场景
```

设计参考 AstrBot 的事件分发和插件 Context、MaiBot 的类型化工具与服务边界。界面参考 [MaiBot 官方 WebUI 展示图](https://github.com/Mai-with-u/MaiBot/blob/v1.3.19/depends-data/webui-millennium-showcase.png) 的模块组织和明暗呈现。
当前代码为独立实现。上游代码引用与后续引入的许可证按实际文件登记；发布前完成许可证清单。
